# Stripe: what the adapter relies on

Checked against Stripe's own documentation on 6 Nov 2026, not memory. Each
line names the page it was read from. Stripe here is the business's own
account and its own keys (not Connect), cards only.

## How the adapter reads them

- Every call sends `Authorization: Bearer <restricted key>` and
  `Stripe-Version: 2026-10-28.endive`. A full `sk_` key is refused at connect
  and never sent.
- Only the currencies in `STRIPE_TWO_DECIMAL` are charged or refunded; any
  other is refused before a call, so a zero- or three-decimal currency is
  never sent in the wrong unit.
- A refund's `Idempotency-Key` is Saroh's reference. Because Stripe replays
  a saved `500` for 24 hours, an unsure refund is settled by `findRefund`
  (matched on `metadata[saroh_refund_id]`, never the amount) or the webhook,
  not by sending the call again.
- `refund.created` may already say `succeeded`, and `refund.updated` says it
  again under another event id: the webhook service settles a refund once
  per provider refund id.

## Not verified

- The exact dashboard label of the Refunds permission: the restricted-keys
  page names "Payment Intents: Write" by example only. Saroh's wording says
  "PaymentIntents: Write and Refunds: Write".
- The full zero-decimal list did not render on the currencies page; the
  adapter does not need it, as it allows only listed two-decimal currencies.
