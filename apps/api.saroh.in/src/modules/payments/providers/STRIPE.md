# Stripe: what the adapter relies on

Checked against Stripe's own documentation on 6 Nov 2026 and again on 8 Nov
2026 (hosted Checkout rows), not memory. Each line names the page it was
read from. Stripe here is the business's own account and its own keys (not
Connect). A customer pays on Stripe's hosted Checkout page (a Checkout
Session, `ui_mode` `hosted_page`) and comes back to the business's site;
the methods are the merchant's dashboard ones, except that a DRAFT invoice
(hold, deposit, pack, plan join) is limited to instant ones.

## How the adapter reads them

- Every call sends `Authorization: Bearer <restricted key>` and
  `Stripe-Version: 2026-10-28.endive`. A full `sk_` key is refused at connect
  and never sent.
- Only the currencies in `STRIPE_TWO_DECIMAL` are charged or refunded; any
  other is refused before a call, so a zero- or three-decimal currency is
  never sent in the wrong unit.
- A payment is a Checkout Session (`cs_…`) with one `price_data` line item
  for the server's amount, `client_reference_id` = Saroh's intent id, and
  `metadata[saroh_ref]` / `metadata[saroh_intent]` on both the session and
  `payment_intent_data[metadata]`, so either a `checkout.session.*` or a
  `payment_intent.*` event finds the row. `payment_intent_data[description]`
  carries the description India exports need. The browser gets only the
  session's `url` and id, never a client secret.
- Instant only (DRAFT invoices): `allowed_payment_method_types[]=card` and
  `=link`; wallets ride on `card`. Everything else sends no method
  parameter, so the merchant's dashboard methods apply.
  `payment_method_types` is never sent (a 400 on this version).
- `billing_address_collection=required` when the account's country is `IN`
  or could not be read (owner, 7 Nov: an unreadable country asks every payer
  for an address; payments never fail for it). Otherwise it is left out
  (`auto`).
- The PaymentIntent is `null` until the customer confirms, so a look-up of a
  `cs_` reads the session with `expand[]=payment_intent`, and cancelling one
  is `expire` (a PaymentIntent of a session can't be cancelled). A `pi_` is
  looked up and cancelled as a PaymentIntent, as before.
- Customers are found by the lower-cased, trimmed email (Stripe's filter is
  case-sensitive and exact) and created only when none is found, with an
  `Idempotency-Key` derived from the business and the email. A customer the
  merchant made with a mixed-case email isn't found, and a second one is
  made.
- A refund's `Idempotency-Key` is Saroh's reference. Because Stripe replays
  a saved `500` for 24 hours, an unsure refund is settled by `findRefund`
  (matched on `metadata[saroh_refund_id]`, never the amount) or the webhook,
  not by sending the call again.
- `refund.created` may already say `succeeded`, and `refund.updated` says it
  again under another event id: the webhook service settles a refund once
  per provider refund id.

## Not verified

- **`GET /v1/account` with a restricted key.** The current API reference
  documents only `GET /v1/accounts/{id}` (permission `connected_account_read`,
  "Direct"), and the permissions reference lists no row for `/v1/account`.
  Whether a restricted key may read it, and under which permission, is
  unconfirmed. The adapter asks once and treats any refusal as "country
  unknown", which requires the billing address (owner decision, 7 Nov).
- **Dashboard labels.** "Payment Intents: Write" and "Customers: Read" appear
  as examples on the restricted-keys page. "Checkout Sessions" (permission
  `checkout_session_write`) and "Refunds" are not shown as labels anywhere
  read; the permissions reference puts `GET /v1/refunds` under `charge_read`,
  so the dashboard row that covers refunds may be named for charges. Saroh's
  words say "Checkout Sessions: Write, Customers: Write, Payment Intents:
  Read and Refunds: Write" until a dashboard screenshot settles them.
- **`expire` on a session that isn't open**: an error, but its HTTP status
  and code are not documented. The adapter reads any 400 as "past expiring"
  (false) and anything else as unsure (throws).
- **`{CHECKOUT_SESSION_ID}` in `cancel_url`**: not documented. The cancel URL
  must carry its own reference.
- **The `checkout.session.*` payloads** in
  `webhooks/providers/__fixtures__/stripe/` are built from the documented
  object, not captured with the Stripe CLI (none was available).
- The full zero-decimal list did not render on the currencies page; the
  adapter does not need it, as it allows only listed two-decimal currencies.
