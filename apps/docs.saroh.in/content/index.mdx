## Saroh, for developers

These are the docs for **running and working on Saroh yourself**. If you use
Saroh on our hosted platform and want to know how to take a booking or chase a
lead, you want [help.saroh.in](https://help.saroh.in) instead.

Saroh is a business workspace: one place a small business sells, takes bookings,
follows up on enquiries, and keeps a website in step. It is a
[pnpm](https://pnpm.io) + [Turborepo](https://turbo.build) monorepo of Next.js
frontends around a single NestJS API.

## The one rule worth knowing first

**`api.saroh.in` is the only service that talks to PostgreSQL.** Every frontend
reaches data through it over HTTP, and none of them import `@saroh/database`.

That is not a style preference. It is what makes tenant isolation checkable in
one place: every org-scoped read resolves an `OrganizationContext` from a proven
session, and the role policy is enforced there rather than in nine apps that
would each drift. If you are adding a feature and reaching for Prisma inside a
Next.js app, the feature belongs behind an endpoint.

## What is in the repository

| Path                     | What it is                                         |
| ------------------------ | -------------------------------------------------- |
| `apps/api.saroh.in`      | NestJS API. Hosts Better Auth. The only DB client. |
| `apps/app.saroh.in`      | The merchant workspace.                            |
| `apps/accounts.saroh.in` | Sign-in / sign-up UI.                              |
| `apps/admin.saroh.in`    | Internal control plane (staff only).               |
| `apps/saroh.in`          | Marketing site.                                    |
| `apps/sites.saroh.in`    | Renders merchants' published sites.                |
| `apps/docs.saroh.in`     | This site.                                         |
| `apps/help.saroh.in`     | Merchant help centre.                              |
| `packages/database`      | Prisma schema, client, migrations, seed.           |
| `packages/ui`            | Shared components and the design tokens.           |
| `packages/auth`          | Better Auth client and shared middleware.          |

## Status, honestly

This is under active development and the schema still moves. Read
[Contributing](/contributing) before relying on any of it in production.

**There is no `LICENSE` file in the repository yet**, and no `license` field in
`package.json`. Until one exists, the terms on which you may run, modify or
redistribute this are not settled — so treat everything here as a description of
how it works, not as a grant of permission. If you are reading this because you
want to run your own copy, open an issue and ask; that is the fastest way to get
the question decided.
